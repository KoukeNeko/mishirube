# Versioning and releases

Four numbers move independently. Confusing them is how a backup stops
opening, so each one says what it promises.

## `version` in `pubspec.yaml`

The app people install, as `major.minor.patch+build`. Semantic for the
user, not for the data: a major release does not imply a new archive
format, and a patch release may contain a schema step.

## `latestSchemaVersion` (`lib/backend/storage/schema.dart`)

The on-device database. It only ever goes up, by appending a step.

- **Never edit a released step.** A step that shipped has already run
  on somebody's phone; changing it means their database and a fresh
  one disagree while both claim the same number. `test/schema_test.dart`
  hashes every step to enforce this.
- Opening a database from a newer app is refused, not migrated down.
  The app says so instead of guessing, because the alternative is
  dropping the columns it does not recognise.
- A step is written so that running it on real data cannot lose a
  column: add tables and columns, backfill, and leave the old ones
  alone until a later release has no readers.

## `archiveFormatVersion` (`lib/backend/import_export/canonical_archive.dart`)

The export file. This is the compatibility promise to the user and to
anything outside this app that reads the format.

- Bump it only for a change that an older app could not read
  correctly. Adding a table or a column does not qualify: unknown
  sections are preserved (`archive_extensions`) and missing ones read
  as empty.
- A file with a higher version is refused with a message that says to
  update, never partially imported.
- `doc/archive.schema.json` is generated from the same table
  definitions and regenerated by the test that checks it. It is never
  edited by hand.

## Engine version constants

Each engine pins what it says about the demo records in
`test/golden/engines.txt`. A deliberate rule change bumps that engine's
constant and updates the snapshot in the same commit. An engine's
version is about the numbers it produces, not about the release.

## Releasing

1. The checks in `AGENTS.md` under **Done means** pass.
2. If a schema step was added, a restore of an archive exported by the
   previous release still round-trips.
3. `version` in `pubspec.yaml` is bumped in its own commit.
4. The tag is the version; the release notes say plainly whether the
   archive format changed, because that is the only part a user has to
   care about.
